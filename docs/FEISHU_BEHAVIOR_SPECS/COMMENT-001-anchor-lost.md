# COMMENT-001 评论锚点丢失

## 用户目标

正文被编辑或删除后，评论讨论不能被系统静默删除。用户应能继续查看、回复、解决或手动删除线程，并明确知道原定位已经失效。

## 数据合同

- 正文保存成功后才检查评论锚点。
- 锚点不存在时，通过评论 PATCH 将状态写为 `anchor_lost`，不调用 DELETE。
- 评论正文、作者、引用、回复关系和时间均保留。
- 如果相同锚点重新出现，将状态恢复为 `open` 或 `resolved`。
- 服务端只接受 `open`、`resolved`、`deleted`、`anchor_lost` 四种状态。

## 交互合同

- `anchor_lost` 线程继续出现在未解决评论侧栏。
- 卡片显示“原评论位置已被删除，评论内容已保留”。
- 原位置跳转和复制锚点链接禁用，回复、解决、编辑和删除继续可用。
- 未实现的翻译、举报入口不显示，避免伪成功反馈。

## 自动化

- Server API 测试覆盖 `anchor_lost` 持久化与非法状态拒绝。
- `comment-threads.spec.ts` 覆盖删除正文锚点后评论仍保留并显示丢失状态。
